# Spike: side-effect-free evaluation via `, nse`

Date: 2026-10-11 · VS version: Visual Studio Community 2026 (DTE `Version` 18.0, build 18.10.12217.157)
Scripts: `scripts/spikes/nse-spike.ps1` (evaluations), `scripts/spikes/nse-spike-driver.ps1` (launches VS on
`samples/OrderDemo`, sets a breakpoint on `var total = Calculate(order);`, runs to it via DTE).

## Question
Does appending the C# `, nse` (no side effects) format specifier to an expression passed to
`EnvDTE.Debugger.GetExpression` prevent the evaluation from mutating program state?

## Output
```
VS version: 18.0
Stopped at: OrderDemo.OrderService.Submit
order.TouchCount             valid=True  value=0
order.Touch(), nse           valid=True  value=1
order.TouchCount             valid=True  value=0
order.Touch()                valid=True  value=1
order.TouchCount             valid=True  value=1
order.Note.Length, nse       valid=True  value=5000
```

## Interpretation
- With `, nse` the debugger still evaluates the call and returns its result (`1`), but the side effect is
  discarded: `TouchCount` stays `0`. This is the documented `nse` semantics (evaluate in a sandbox), slightly
  different from the plan's expectation that the expression would be rejected; the property that matters —
  no mutation of program state — holds.
- Without `, nse` the same call mutates state (`TouchCount` becomes `1`), so the control experiment confirms
  the test can detect side effects.
- `, nse` on a plain property read returns the normal value.

## Decision
NSE_SUPPORTED = true

`eval` and `vars(path)` append `, nse` (plan Task 9 Step 7a).
